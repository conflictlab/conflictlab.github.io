# Monthly Runbook — PaCE Website

This runbook lists what needs to run each month so the public website and API stay current, with exact locations and manual triggers.

## Repositories

- Forecasting (compute): conflictlab/Pace-map-risk
- Website (this site): conflictlab/conflictlab.github.io

## Monthly Timeline (UTC)

- 28th @ 01:00 — Forecast generation (in forecasting repo; see below)
- 28th @ 03:00/04:00 — Website data updates (pre-month safety run)
  - Min/max + scenarios (03:00): `.github/workflows/update-minmax.yml`
  - Matches JSON (04:00): `.github/workflows/update-matches.yml`
- 28th @ 03:00 — Forecast CSV sync + grid/static API build: `.github/workflows/sync-forecasts.yml`
- 28th after updates — Deploy to GitHub Pages: `.github/workflows/deploy-pages.yml`
- 28th @ 06:00 — Health check: `.github/workflows/health-check.yml`
- 1st @ 01:00 — Forecast generation (compute repo, fallback)
- 1st @ 03:00/04:00 — Website data updates (fallback)
- 1st @ 03:00 — Forecast CSV sync + grid/static API build (fallback)
- 1st after updates — Deploy to GitHub Pages; Health check @ 06:00

Tip: A one-click manual refresh exists: `.github/workflows/refresh-website.yml` (see Manual Triggers).

## Website Workflows (this repo)

- Sync Forecast CSVs — `.github/workflows/sync-forecasts.yml`
  - Runs on the 28th and 1st. Pulls latest CSV(s) from forecasting repo, snapshots JSON, rebuilds grid assets (centroids, GeoJSON, monthly points, CSVs), exports static API, updates `public/status.json`, commits changes.
  - Manual: Actions → “Sync Forecast CSVs” → Run workflow.

- Update minmax and denorm scenarios — `.github/workflows/update-minmax.yml`
  - Runs on 26th/28th/1st. Downloads `sce_dictionary.pkl`, converts to `public/data/scenarios.json`, recomputes `public/data/minmax.json`, writes `public/data/scenarios.denorm.json`, updates `public/status.json`, commits.
  - Manual: Actions → “Update minmax and denorm scenarios” → Run workflow.

- Update DTW matches JSON — `.github/workflows/update-matches.yml`
  - Runs on 26th/28th/1st. Downloads `saved_dictionary.pkl`, converts to `public/data/matches.json`, updates `public/status.json`, commits.
  - Manual: Actions → “Update DTW matches JSON” → Run workflow.

- Deploy to GitHub Pages — `.github/workflows/deploy-pages.yml`
  - Auto-triggered after the above via `workflow_run`. Builds static `out/`, uploads, deploys Pages. Also ensures `public/status.json` present.
  - Manual: Actions → “Deploy to GitHub Pages” → Run workflow.

- Health Check (Live Site) — `.github/workflows/health-check.yml`
  - Runs daily and after deploys. Fetches deployed `/status.json` and a sample static API endpoint; checks remote `forecast_metadata.json` freshness. Opens an issue and emails on failure.
  - Manual: Actions → “Health Check (Live Site)” → Run workflow.

- Refresh Website Now (one-click) — `.github/workflows/refresh-website.yml`
  - End-to-end: sync forecasts + rebuild grid/static API + update scenarios/minmax + update matches + status.json + commit + push; deploy auto-runs afterward.
  - Manual: Actions → “Refresh Website Now” → Run workflow.

- Test Email — `.github/workflows/test-email.yml`
  - Sends a quick test via SMTP. Provide `to` (and optional `from`) when running.

## Forecasting Repo (compute)

- Repo: conflictlab/Pace-map-risk
- Monthly forecast generation workflow (see repo Actions):
  - Downloads latest UCDP
  - Computes h=6 and h=12 forecasts
  - Outputs (raw base read by site):
    - `forecasts_h6.csv`, `forecasts_h12.csv`, `Hist.csv`, `forecast_metadata.json`
    - Optional: `Historical_Predictions/` monthly CSVs
- Manual: In that repo, Actions → “Generate Monthly Forecasts” (or similarly named) → Run workflow.

## Monitoring & Status

- Status JSON: `public/status.json` (generated by `scripts/generate-status.js`)
- Status page: `/status` (UI at `app/status/page.tsx`)
- Live checks: `scripts/check-live.js` (follows redirects). Used by health-check workflow.

## Secrets and Variables (this repo)

- SMTP/email (for notifications):
  - `SMTP_SERVER`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USERNAME`, `SMTP_PASSWORD`
  - `MAIL_FROM` (e.g., `PaCE Bot <bot@yourdomain.com>`), `MAIL_TO` (comma-separated)
- Optional repo vars for data pickles:
  - `SCE_REPO`, `SCE_BRANCH`, `SCE_PATH` (defaults to `conflictlab/Pace-map-risk@main`, `sce_dictionary.pkl`)
  - `MATCHES_REPO`, `MATCHES_BRANCH`, `MATCHES_PATH` (defaults to `conflictlab/Pace-map-risk@main`, `saved_dictionary.pkl`)

Email behavior:
- Success + failure: minmax/scenarios, matches, deploy, refresh-all
- Failure-only: daily sync, health-check

## Manual Monthly Run (step-by-step)

1) (Optional) Recompute forecasts in forecasting repo:
   - Conflictlab/Pace-map-risk → Actions → run the monthly generation.

2) Refresh the website (one-click):
   - This repo → Actions → “Refresh Website Now”. Deploy auto-runs afterward.

3) Verify:
   - This repo → Actions → “Health Check (Live Site)” → confirm status OK.
   - Browse `/status` and sample API `/api/v1/grid/<latest>/points-m1.json`.

## Validation Checklist

- `forecast_metadata.json` run_date is recent (≤ 45 days)
- `/status.json` ok=true; static API available for latest period
- Pages deploy completed; site accessible
- No open “Health check failed” issues
